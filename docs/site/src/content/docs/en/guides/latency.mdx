---
title: Latency
description: What shapes perceived latency, knobs to tune, and how to measure.
---

Perceived latency is not one HTTP round-trip. It is the full pipeline:

**local turn detection → upload → model TTFT / first PCM → player queueing**

Typical turn:

1. User speaks → Session tracks local microphone volume
2. Live chunks hit ASR; `asr_partial` keeps updating
3. Sustained local silence closes the turn → `user_audio_end`
4. The first complete LLM clause enters TTS while later tokens keep arriving
5. The first PCM packet is enqueued → `assistant_audio_start`

## Practical levers

1. Prefer **streaming ASR** with partials for responsive captions. Stable ASR
   segments remain transcript data; local VAD owns the turn boundary.
2. Tune `silenceTimeoutMs` on target devices. The web example starts at
   **500 ms**; noisy rooms or deliberate speakers may need a longer value.
3. Implement both `LLMProvider.stream()` and `TTSProvider.stream()`. Core sends
   the first complete sentence/clause to TTS immediately; without streaming
   TTS it still falls back to sentence-sized `synthesize()` calls.
4. Reuse connections and playback; cap reply length and `maxTokens`.
5. Use stricter `interruptionDetection` during playback so echo does not false-trigger, without delaying real barge-in.

## How to measure

| Interval | Events | Meaning |
| --- | --- | --- |
| Turn end → first audio | `user_audio_end` → `assistant_audio_start` | **Perceived first-audio latency** (primary KPI) |
| Turn end → first text | `user_audio_end` → first `assistant_text_delta` | Text TTFT |
| Live captions | First `asr_partial` | Input-side feel |

Sample on target devices, speaker volume, and real noise — not only a quiet lab.

## Compatibility path

**Rolling partials** (batch ASR) re-upload accumulated audio — fine for demos.
Prefer native WebSocket streaming ASR (Deepgram / ElevenLabs) in production.
ASR adapters expose provisional and final transcript segments only. Turn
closure stays independent of provider segmentation and network inference.

See [`TurnDetectionConfig`](/docs/en/packages/core/), [`policy`](/docs/en/packages/core/), and the [events guide](/docs/en/guides/events/).
